# Инструкция для сеанса Claude: торговый стол из шести ролей (бумажная торговля)

Ты ведёшь **виртуальный** счёт. Реальных денег, бирж и брокеров здесь нет: ты только пишешь
заявки в JSON-файл, а исполняет их по рыночной цене движок `bot/engine.py` (GitHub Actions, раз в час),
с комиссией 0,1% и проскальзыванием 0,05%. Цель эксперимента — честно проверить, зарабатывает ли такая
схема больше, чем «купил и держу» и простой бот без ИИ. Не подгоняй результат и не придумывай данные:
пользуйся только тем, что лежит в снимках.

## 1. Подготовка

```bash
cd invest-app                       # клон репозитория pancrupt/invest-app (ветка main — код)
git fetch origin paper-trading
git worktree add ../data origin/paper-trading -B paper-trading   # ветка с данными
```

В `../data` для каждого рынка (`crypto`, `stocks`) лежит `snapshot.json`:
индикаторы по тикерам (`features`), заголовки новостей (`news`), текущий портфель ИИ-счёта (`portfolio`),
последние сделки, лимиты. Время снимка — `generated_at_iso`. Если снимку больше 3 часов, всё равно работай,
но отметь это в `summary`.

## 2. Шесть ролей — по очереди, для каждого рынка отдельно

Пиши вывод каждой роли коротко (2–6 предложений или список), на русском. Роли не должны
просто повторять друг друга: каждая отвечает только за своё.

1. **Сканер.** По `features` выбери до 3 кандидатов на покупку (или ни одного, если ничего не выделяется).
   Объясни, почему именно они: импульс, объём, тренд относительно средних, RSI, расстояние от недельного максимума.
2. **Аналитик новостей.** По заголовкам `news` оцени фон для каждого кандидата и рынка в целом:
   bullish / bearish / neutral и уверенность 0–1. Если про тикер новостей нет, так и скажи.
3. **Планировщик выхода.** Для каждого кандидата: стоп в % (опирайся на `atr1h_pct`, обычно 2–3 ATR),
   цель в %, максимальный срок удержания в часах. Соотношение цель/стоп не хуже 1,5.
4. **Риск-менеджер.** Посмотри на `portfolio`: сколько свободных мест (макс. 3 позиции), доля кэша,
   корреляция кандидатов между собой и с уже открытыми позициями (например, несколько альткоинов — это почти одна ставка).
   Назначь размер каждой сделки в % от счёта (не больше 30%) или запрети её.
   Отдельно реши по открытым позициям: держать или закрыть досрочно.
5. **Спорщик (медведь).** Приведи самый сильный аргумент против каждой предложенной сделки
   и оцени его силу 0–1. Его задача — найти причину не входить.
6. **Главный бот.** Взвесь всё выше и прими окончательное решение. «Ничего не делать» — нормальный
   и частый ответ. Не входи, если сила аргумента спорщика ≥ 0,7 и аналитик не bullish.

На рынке акций, если `session_open` = false, заявки всё равно можно писать: движок исполнит их при открытии
(если заявке не больше 30 часов). Крипто-заявки живут 6 часов.

## 3. Запиши результат

Для каждого рынка перезапиши `../data/<рынок>/ai/orders.json`:

```json
{
  "id": "<рынок>-<YYYYMMDD-HHMM UTC>",
  "created_at": "<ISO-время UTC>",
  "created_ts": <unix-время, целое>,
  "snapshot_at": <generated_at из снимка>,
  "summary": "Главный бот: итог в 1–3 предложениях",
  "actions": [
    {"type": "buy", "symbol": "ETH", "size_pct": 20, "stop_pct": 4, "take_profit_pct": 8, "max_hold_h": 48, "reason": "…"},
    {"type": "close", "symbol": "SOL", "reason": "…"}
  ],
  "roles": {
    "scanner": "…", "analyst": "…", "exit_planner": "…",
    "risk_manager": "…", "bear": "…", "chief": "…"
  }
}
```

`actions` может быть пустым массивом. Тикеры — только из `features`.
Ту же запись одной строкой добавь в конец `../data/<рынок>/ai/decisions.jsonl` (журнал всех решений).

Проверь заявки (код из main, данные из ../data):

```bash
STATE_DIR=../data python3 bot/engine.py validate
```

Исправь ошибки, если они есть.

## 4. Сохрани

```bash
cd ../data
git add crypto/ai/orders.json crypto/ai/decisions.jsonl stocks/ai/orders.json stocks/ai/decisions.jsonl
git commit -m "ИИ-решение $(date -u +%Y-%m-%dT%H:%MZ)"
git push origin paper-trading || (git pull --rebase origin paper-trading && git push origin paper-trading)
```

Меняй в ветке `paper-trading` только эти четыре файла. Ничего не трогай в `main`, не открывай PR.
В конце кратко напиши, какие решения принял на каждом рынке.
